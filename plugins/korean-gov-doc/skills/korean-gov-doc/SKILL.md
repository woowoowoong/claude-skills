# 관공서 한글 문서 작성·조판

공공기관 제출 문서는 **내용이 아니라 형식에서 먼저 걸린다.** 서술체로 쓰면 "AI가 만든 느낌"이라는 반응이 나오고, 양식표를 임의로 바꾸면 반려된다. 이 스킬은 개조식 본문 규칙, 조판 수치, 공고문 양식 재현 방법, md → docx 빌드 파이프라인을 담는다.

## 작업 순서

1. **공고문·과업지시서를 먼저 읽는다.** 목차(안), 분량 제한, 제출 양식(갑지·요약표), 평가 기준 배점을 추출한다. 목차(안)이 있으면 그대로 따른다 — "자유롭게 구성 가능"이라고 쓰여 있어도 목차를 바꾸면 심사위원이 대조하기 어려워진다.
2. **본문을 Markdown으로 쓴다.** 개조식 규칙(아래)을 지킨다.
3. **양식 페이지는 raw OOXML로 만든다.** 갑지·요약표처럼 세로병합이 필요한 표는 pandoc 파이프 표로 불가능하다.
4. **빌드하고 검증한다.** `assets/build_docx.py` → `validate.py --original` → PDF 변환 후 페이지 이미지로 눈으로 확인.

분량이 "○○page 내외"로 제한되면, **갑지·요약·목차·부록은 본문 분량에서 제외**하고 계산한다. 본문이 제한치를 넘으면 서술을 줄이지 말고 표로 압축한다.

## 개조식 본문 규칙

계층은 세 단계까지만 쓴다. 그 아래로 내려가면 읽는 사람이 위치를 놓친다.

```
**□ 중분류** — 한 줄 요약을 붙일 수 있음
　○ 소분류 항목
　　- 세부 항목
```

들여쓰기는 **전각공백 U+3000(`　`)** 으로 한다. 반각 공백은 Word에서 폭이 들쭉날쭉하다.

- **명사형으로 끝낸다.** "~함", "~임", "~필요", "~가능". "~합니다", "~됩니다"는 쓰지 않는다.
- **한 항목은 한 줄.** 두 줄을 넘기면 하위 항목으로 쪼갠다.
- **주어를 반복하지 않는다.** □ 제목이 주어 역할을 한다.
- 어려운 한자어는 풀어 쓴다. "양자를 구분 담지" → "둘을 나누어 담음". 심사위원이 해당 분야 전문가가 아닐 수 있다.
- 확정되지 않은 수치는 `【 】`로 비워 두고, 표지에 "【 】 는 ~ 시점에 기입할 항목"이라고 명시한다.
- **수행 전인 결과표는 반드시 "기재 양식(예시)"으로 표기한다.** 실측 전 수치를 결과처럼 제시하면 허위 기재가 된다. 표 제목에 "— 작성 양식(예시)"을, 그림 캡션에 "(양식·예시)"를 붙인다.

## 조판 수치

`assets/styles.xml`이 이 값들을 담은 pandoc reference-doc이다. 수정할 일이 있을 때만 아래를 참조한다.

| 항목 | 값 |
|---|---|
| 본문 글꼴 | 맑은 고딕 10pt |
| 줄간격 | 105% (`w:line="252" w:lineRule="auto"`) |
| 정렬 | **좌측 정렬** — 양쪽 정렬은 개조식 짧은 줄을 늘려 놓아 금지 |
| 제목1 | 14pt bold + 하단 실선 |
| 제목2 | 11pt bold |
| 용지 | A4 (11906 × 16838 twips), 여백 상 1304 / 하 1247 / 좌우 1021 |

문단 간격은 빌드 스크립트가 자동으로 넣는다. 값은 `build_docx.py` 상단 상수에 있다.

| 위치 | 여백 |
|---|---|
| □ 항목 앞 | 170 twips (8.5pt) |
| ※ 단서 앞 | 60 twips (3pt) |
| 표 바로 앞 문단 뒤 | 90 twips |
| 표 바로 뒤 문단 앞 | 130 twips |
| ○ / - 항목 사이 | 없음 (붙임) |

□ 사이를 띄우지 않으면 "위아래로 딱딱 붙어 있다"는 지적을 받는다. 반대로 ○ 사이까지 띄우면 산만해진다.

## 표

- 머리행 : 음영 `D9D9D9` + bold + 세로 가운데 정렬
- 테두리 : 바깥 0.75pt `#404040`, 안쪽 0.5pt `#808080`
- **짧은 열(단계·No.·단위·수치·①②)은 가운데 정렬, 긴 열(항목명·설명)은 좌측 정렬**
- 열 너비를 명시하지 않으면 pandoc이 균등 분할해서, 짧은 항목 열이 넓고 긴 설명 열이 좁아진다

pandoc 파이프 표에서 열 너비를 지정하려면 **구분선 전체 길이가 약 72자를 넘어야 한다.** 그보다 짧으면 상대 폭이 무시된다.

```
| 단계 | 수행 내용 | 산출물 |
|:------:|:-------------------------------------------------------------|:-------------------------|
```
`:---` 좌측 정렬 / `:---:` 가운데 정렬. 대시 개수가 상대 폭이 된다.

자세한 내용과 헬퍼 함수는 `references/tables.md`.

## 그림

Word 문서라도 도해는 필요하다. 다만 관공서 도해 문법을 지킨다 — **각진 사각형, 검정 실선, 흰 배경, 점선 그룹박스 + 어두운 라벨 탭.** 둥근 모서리·그라데이션·아이콘·여러 색은 "AI가 만든 느낌"으로 읽힌다. **강조는 한 가지 색만** 쓴다.

캡처를 나중에 받아야 하면 실제 크기의 삽입 영역을 미리 잡아 둔다. `build_docx.py`의 `FIG_MM`에 그림 번호별 높이(mm)를 넣으면 점선 박스가 생기고, `figs/figNN.png`가 있으면 실제 이미지로 대체된다. **그림 번호는 읽는 순서대로 오름차순**이어야 하므로 절을 옮기면 번호도 함께 재정렬한다.

## 공고문 양식 재현

갑지와 요약표는 공고문 원본 그대로 재현한다. 라벨을 바꾸거나 항목을 빼면 안 된다.

**갑지** — 제목 / 참가 주제명 / 날짜 / 업체 표(구분·업체명·대표자·직인). 직인란은 행 높이를 600 twips 이상 잡는다.

**요약표** — 라벨 셀이 세로 병합된 구조가 대부분이다. pandoc으로는 만들 수 없으므로 raw OOXML로 생성한다. `assets/ooxml_form.py`에 `tbl / tr / tc / para` 헬퍼가 있다.

표지에 머리글·쪽번호가 나오지 않게 하려면 `sectPr`에 `<w:titlePg/>`와 첫 페이지용 빈 header/footer를 넣는다. `<w:titlePg/>`는 `<w:cols>` 뒤, `<w:docGrid>` 앞에 와야 한다.

## Word / LibreOffice 렌더 차이

**여기서 확인하는 PDF는 LibreOffice로 뽑은 것이고, 사용자는 Word로 연다.** 한글 줄높이 계산이 달라 Word가 약 10% 높게 잡힌다. 빈 문단으로 여백을 만들면 오차가 누적되어 표지나 양식표가 다음 장으로 밀린다.

- **고정 레이아웃(표지 등)은 빈 문단 대신 `w:line="N" w:lineRule="exact"`로 높이를 직접 고정한다.** 그러면 두 프로그램이 동일하게 렌더한다.
- **본문이 줄바꿈되는 양식표는 높이를 고정할 수 없으므로 여백으로 흡수한다.** LibreOffice 기준 페이지의 70% 이하로 채워야 Word에서 안전하다. 80%를 넘으면 넘칠 가능성이 높다.
- 표가 페이지 경계에 걸려 머리행만 다음 장에 남으면, 열 너비를 조정해 줄바꿈 두어 줄을 없애는 것이 가장 확실한 해결책이다.

## 빌드

```bash
python3 build_docx.py                                    # md → docx
python3 <docx-skill>/scripts/office/validate.py out.docx --original ref.docx
soffice --headless --convert-to pdf --outdir . out.docx
pdftoppm -r 72 -png out.pdf pg/p                         # 페이지 이미지로 눈 확인
```

`--original`을 주지 않으면 reference-doc이 원래 갖고 있던 무해한 스키마 경고까지 새 오류로 잡힌다.

**pandoc이 만드는 OOXML은 스키마를 자주 위반한다.** `build_docx.py`가 보정하는 항목과 요소 순서 규칙은 `references/ooxml-pitfalls.md`에 정리되어 있다. 후처리를 새로 추가할 때 반드시 읽는다.

`---` 두 줄을 연속으로 쓰면 페이지 나눔이 된다.

```

---
```
